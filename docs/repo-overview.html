Agent Autopsy

A local-first debugger that normalizes AI-agent traces, detects deterministic failure patterns, and optionally adds LLM-assisted root-cause analysis.

Evidence-backedLocal-first HTMLSource inspected

The problem it solves

Agent traces are easy to collect but difficult to turn into evidence-backed fixes. Agent Autopsy gives developers a local, deterministic first pass before they spend tokens or upload sensitive traces.

Current features

  • LangGraph, LangChain, OpenTelemetry, generic JSON, and plugin-defined ingestion
  • Common trace schema and deterministic pre-analysis
  • Detectors for loops, retries, redundant calls, hallucinated tools, auth/timeouts, drift, stale context, token waste, overflow, and contract mismatches
  • Markdown/JSON reports, evidence references, fix suggestions, and artifacts
  • CLI analysis, summaries, validation, diffs, watch, replay, benchmark, monitor, and fixes
  • Streamlit UI, MCP tools/resources/prompts, trace capture helpers, plugins, LLM synthesis, and caching

Main execution flow

  1. Detect the input format and parse the trace.
  2. Normalize events, timing, tokens, errors, tool calls, and handoffs into the shared schema.
  3. Run deterministic pattern and contract checks, then build evidence-linked hypotheses.
  4. Render a deterministic report or, when configured, pass the normalized evidence to the LLM analysis graph.
  5. Return terminal/UI/MCP output and optionally write report and fix artifacts.

Major components

TraceParser + format parsers

Format detection for LangGraph, LangChain, OpenTelemetry, generic JSON, and plugins.

PatternDetector

Deterministic failure catalogue and evidence references.

ContractValidator / RootCauseBuilder

Contract violations and ranked hypotheses.

Budgeted LangGraph investigation, synthesis, and report quality checks.

Trace analysis, pattern detection, comparison, health, benchmark, monitoring, and resources.

PluginManager

Parser, detector, report, fix, and visualization extension points.

Commands below are taken from the repository. Run them from the project root unless the first command changes directory.

source .venv/bin/activate
python -m pip install -e .

streamlit run app.py
pip install -e ".[dev]"

Example input and output

Input

examples/traces/loop_failure.json: a failed weather lookup with seven repeated web_search timeouts followed by MaxRetriesError.

Output

The walkthrough expects failed status, loop/retry findings, iteration-guard and retry-control fixes, and a materially reduced health score.

PyPI packaging exists, but the status tracker says the upload still awaits maintainer credentials. Full local test verification was interrupted by a Hugging Face model lookup.

planned

Roadmap items include detector tuning, a stable 10 MB performance fixture/CI threshold, CLI splitting, and optional structured-only LLM output.

Known limitations and technical debt

  • Optional semantic-drift and LLM paths introduce model downloads, credentials, network behavior, cost, and nondeterminism.
  • The full test run can reach a Hugging Face lookup rather than remaining entirely hermetic in the inspected environment.
  • Checked-in agent_autopsy.egg-info and legacy scripts/modules overlap with package metadata and source responsibilities.
  • Several broad planning/audit documents coexist with the current README and phase status, making the authoritative roadmap less obvious.

Repository audit

Strongest parts

  • Deterministic-first design with concrete evidence references
  • Wide input and interface coverage without making LLM use mandatory
  • Substantial tests and honest optional-dependency boundaries

Confusing or undocumented

  • Current status is split across README, ROADMAP, implementation audit, phase status, and multiple improvement plans
  • scripts/modules appears to preserve older analyzer/report implementations beside src/

Unused or duplicated

  • Checked-in agent_autopsy.egg-info is generated packaging metadata
  • scripts/modules/trace_analyzer.py and report_generator.py overlap conceptually with src/analysis and src/output
  • requirements.txt is a Streamlit deployment shim rather than an independent dependency source

Recommended README improvements

  • Add a single current-status table linking shipped, optional, and planned capabilities
  • Document whether full tests require or download embedding models
  • Mark legacy scripts/modules and generated egg-info explicitly

Five highest-priority improvements

  • Make the default test suite network-hermetic
  • Consolidate roadmap/status documents
  • Remove or document checked-in generated and legacy modules
  • Add the 10 MB no-LLM performance gate
  • Publish and document an actual package release when credentials are available
